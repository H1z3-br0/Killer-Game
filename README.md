# Киллер

Внутренний сервис для игры «Киллер» (Assassin) в локальной сети организации.
Каждый участник получает одну цель и сам является чьей-то целью; все связаны в
**один замкнутый круг**. Устранил цель — наследуешь её жертву, круг сжимается,
пока не останется один.

Полное техническое задание — в [SPEC.md](SPEC.md).

## Запуск

```bash
./run.sh                 # поднимет venv, поставит зависимости, запустит сервер
PORT=9000 ./run.sh       # на другом порту
```

Сервис слушает `0.0.0.0:8000`, чтобы открываться с телефонов в той же сети.
Первый зарегистрировавшийся становится **сисадмином** — отдельной установки не
требуется.

Один процесс, `--workers 1`: применение игровых событий должно быть строго
последовательным, и блокировка живёт в памяти процесса.

## Устройство

```
app/
  main.py          приложение и обработчики ошибок
  config.py        настройки (переменные KILLER_DB, KILLER_BACKUPS, ...)
  db.py            SQLite, миграции, транзакции, аудит
  security.py      argon2, токены, нормализация ФИО, лимиты частоты
  auth.py          сессии, текущий пользователь, CSRF
  game_logic.py    ЯДРО: круг, события, инвариант, заявки, откат
  repo.py          запросы чтения (цепочку не отдаёт ни одна функция)
  settings_store.py настройки платформы
  routes/          auth_routes, games, admin_game (ведущий), sysadmin
  templates/       Jinja2, русский интерфейс, мобильный по умолчанию
  static/          app.css, app.js — без внешних зависимостей
migrations/        нумерованные .sql, применяются по одному разу
tests/test_flow.py сквозной сценарий от регистрации до победителя
```

## Главные правила, зашитые в код

- **Цепочку не отдаёт ни один эндпоинт.** Имя цели возвращает только
  `POST /games/{id}/target/reveal` и только своему владельцу — в HTML страницы
  его нет. Прочитать круг целиком можно лишь из файла базы.
- **Инвариант проверяется после каждого события.** Живые образуют ровно один
  замкнутый цикл; если нет — транзакция откатывается (`ChainBroken`).
- **Цепочку меняют две операции, обе у сисадмина:** вывод участника и откат
  последнего события. Ведущий игры шлёт заявку.
- **Откатить можно только последнее событие** — иначе последующие пересшивания
  теряют смысл.
- **Личность берётся из сессии, никогда из запроса.**
- **Логин уникален, ФИО — нет.** Человек придумывает логин сам и входит с ним;
  ФИО остаётся отображаемым именем, поэтому тёзки не конфликтуют.
- **Молчание приглашённого к моменту старта — отказ.**

## Фоновые задачи

Планировщик крутится в том же процессе и раз в минуту:

- завершает игры с наступившим дедлайном (победа по числу устранений, при
  равенстве — устранивший раньше);
- проверяет инвариант круга во всех активных играх и пишет в журнал ошибок,
  если он нарушен;
- убирает истёкшие одноразовые коды и счётчики частоты;
- раз в сутки делает бэкап (`killer-auto-ГГГГ-ММ-ДД.db`, хранятся последние 14).

## Эксплуатация

| Куда | Зачем |
|---|---|
| `/admin` | обзор: люди, игры, заявки, аптайм, размер базы |
| `/admin/users` | поиск, карточка, блокировка, сброс пароля, удаление |
| `/admin/duplicates` | похожие ФИО — опечатки при регистрации, слияние записей |
| `/admin/support` | заявки: сброс пароля, конфликт ФИО, вывод участника |
| `/admin/games` | все игры, вывод участника, откат последнего события |
| `/admin/integrity` | проверка кругов во всех активных играх по кнопке |
| `/admin/maintenance` | аптайм, место на диске, ошибки, ручная уборка |
| `/admin/backups` | копии, восстановление (ставит игры на паузу) |
| `/admin/audit` | журнал админских действий, из интерфейса не очищается |

Автозапуск: `deploy/killer.service` (systemd) или `deploy/com.killer.plist`
(launchd, macOS).
